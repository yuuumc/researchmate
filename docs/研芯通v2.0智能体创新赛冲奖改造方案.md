4. **Agent Trace 可视化**：竞品普遍黑盒；研芯通已透明化，是演示杀手锏。
5. **面向工科科研成长**：定位「工科 AI 导师」而非「考研工具」，竞赛叙事更高一档。

> **一句话定位（升级版）**：
> 研芯通——面向工科学生全生命周期的**多智能体 AI 导师**，通过 5-Agent 协作、知识图谱图检索增强（GraphRAG）、学生认知模型与长期学习记忆，实现「课程学习 → 能力诊断 → 成长规划 → 科研实践」的全过程智能陪伴，并为教师提供班级级洞察。

## 五、核心技术改造细节

### 5.1 P0-1：GraphRAG（图增强检索）

**现状**：`src/utils/rag.js` 用 TF-IDF + 子串混合检索切片；`knowledgeGraph.js` 用 JSON 图谱做前置知识链。两者未联合。

**改造成目标**：
```
问题
 ├→ 向量检索（embedding 近似召回 Top-K 切片/节点）
 ├→ 图谱检索（命中节点 → 邻域遍历 → 前置知识链）
 └→ 联合重排（向量相似度 + 图谱邻近度加权）→ 最终上下文
```

**落地（零外部服务，保持不引重依赖）**：
- 用 `Intl.Segmenter` 分词 + 轻量词向量哈希（避免引重型向量库），或接入 Supabase `pgvector`（已用 Supabase，成本低）
- `knowledgeGraph.js` 增加 `graphRetrieve(query, topK)`，与 `rag.js` 的 `retrieve` 双路并行
- 返回结构升级为 `{ vectorHits, graphHit, mergedContext }`，供 Agent Trace 展示「图检索命中」

**评审话术**：`"我们把知识图谱从'静态 JSON + 关键词'升级为'图结构 + 向量语义'双路联合检索——这是 2026 GraphRAG 的主流做法，让回答既懂语义又懂逻辑依赖。"`

### 5.2 P0-2：Agent 工具调用（MCP / Function Calling）

**现状**：`BaseAgent.js` 只有 LLM 调用，Agent 无外部工具。

**改造**：
- 在 `BaseAgent.js` 增加 `registerTool(name, fn, schema)` + `callTool(name, args)`
- 首批工具：
  | 工具 | 用途 | 服务 Agent |
  |---|---|---|
  | `search_knowledge(question)` | 检索知识库 | Tutor |
  | `query_university(constraint)` | 按分数/地区查院校 | Admission |
  | `store_progress(ability, star)` | 写回能力星级 | Diagnose/Planner |
  | `generate_plan(weeks, hours)` | 生成计划 | Planner |
  | `recommend_papers(direction)` | 检索论文 | Research |
- LLM 输出结构化 `{"tool": "...", "args": {...}}` → 执行 → 回填结果 → 继续生成

**评审话术**：`"我们的 Agent 不只是'对话'，它能调用真实工具——查院校、写进度、检索论文。这是大模型从'语言模型'走向'行动体'的关键一步。"`

### 5.3 P0-3：三层记忆系统

**现状**：`persist.js` + localStorage 存 profile/history/plan。

**改造**：
```
短期会话记忆（本轮对话上下文）
   ↓ 摘要沉淀
长期画像记忆（profile：能力星级/弱项/目标/风格）
   ↓ 向量化
向量记忆（历史诊断/问答的 embedding，供相似问题召回）
```
- 会话记忆：`ChatWindow` 维护；结束或轮次 N 时摘要写入画像
- 画像记忆：现有 profile 强化，新增 `profile.memory` 摘要字段
- 向量记忆：历史诊断/回答向量化，新问题先检索"我过去是否问过类似问题"

**评审话术**：`"Agent 区别于聊天机器人的核心是'记住用户'。我们做了三层记忆：短期会话、长期画像、向量记忆——所以它知道你的能力星级、上次错在哪、规划迭代到第几版。"`

### 5.4 P0-5：评审演示剧本（5 分钟叙事）

将现有 Agent Trace、知识图谱路径卡、旗舰旅程串成一个「有主角、有冲突、有成长」的故事：

1. **0:00-0:30 痛点 + 定位**：研芯通 = 工科 AI 导师，不是考研工具
2. **0:30-1:30 多 Agent + GraphRAG**：输入概念问题 → 看 Agent Trace 实时展示 Router 识别 → 知识图谱路径卡 → 前置知识引导
3. **1:30-2:30 诊断→规划→科研 旗舰旅程**：三步级联，看画像更新、计划迭代
4. **2:30-3:30 工具调用 + 记忆**：Agent 调工具查院校/写进度；切换学科验证「换知识库=换专业」
5. **3:30-4:30 教师端 + 数据**：班级统计、学生画像、薄弱点洞察
6. **4:30-5:00 技术亮点 + 安全 + 效果数据**：GraphRAG、SSE 流式、API Key 防泄漏、beta 数据

# 附录 A · P0-1 GraphRAG 详细技术设计

> 本节为 P0-1「知识图谱升级为 GraphRAG」的落地级设计，供开发直接执行。
> 状态：**步骤 2 已实现**（`src/utils/knowledgeGraph.js` 的节点向量索引 + `graphRetrieve`），其余步骤待开发。

## A.0 现状与目标

**现有链路**（`tutor.js` → `rag.js` + `knowledgeGraph.js`）：
```
问题 → TF-IDF+子串检索 Top-5 切片 → 取 topSlice.id → findNodeBySourceId 反查节点
     → 前置知识链 → 个性化回答
```
弱点：① 检索是**词法**（TF-IDF），不认语义；② 图谱是**静态 JSON**，只做"反查 + 前置链"，没参与检索打分；③ 向量能力为 0。

**GraphRAG 目标**：
```
问题 → [向量检索 Top-K 节点] ═╗
     → [图谱检索命中节点]     ╠→ 联合重排 → 前置知识链 → 个性化回答
     → [TF-IDF 检索 Top-K 切片]╝
```

## A.1 依赖库选型评估

| 方案 | 依赖 | 是否引入 | 理由 |
|---|---|---|---|
| 纯前端 TF-IDF + 图谱（现状） | 无 | ✅ 保留 | 兜底，浏览器端零依赖 |
| **前端轻量向量**（特征哈希/近邻） | 无 | ✅ 采用 | 零依赖，够演示 |
| Supabase `pgvector` | `@supabase/supabase-js`（已装） | ⭕ 可选增强 | 服务端向量更"真"，但需建表+embedding |
| `@xenova/transformers`（本地 embedding） | 新依赖 ~40MB | ⚠️ 慎选 | 真 embedding 但体量大 |
| OpenAI/DeepSeek embedding API | 需后端 proxy | ⚠️ 可选 | 正规但依赖外部 API + 成本 |
| LangGraph / LangChain | 新依赖 | ❌ 不引入 | 重度框架，违背"不加重依赖" |

> **结论**：主路径零新增重型依赖，用「特征哈希向量 + 图谱邻域」双路，完全贴合项目强约束。

## A.2 已实现 · 步骤 2：图谱向量化（`src/utils/knowledgeGraph.js`）

- `textToVector(text)`：`tokenize` → FNV-1a 特征哈希到 256 维 → 词频累加 → L2 归一化，返回 `Float64Array`。
- `cosineSimilarity(a, b)`：余弦相似度。

## A.3 待开发 · 步骤 3：双路联合重排

### 输入 / 输出契约
```
graphRagRetrieve(query, { knowledgeBase, graph, profile }, opts)
  → {
      vectorHits,   // [{slice, vecScore}]  向量路召回切片
      graphHits,    // [{node, graphScore, prerequisites, mastery}]  图谱路召回节点
      merged,       // [{kind:'slice'|'node', key, score, ...}]  联合重排 Top-K
      bestNode,     // 图谱路最高分节点（供知识路径卡）
    }
```

### 三条召回路径（并行）
| 路 | 函数 | 召回对象 | 原始分量纲 |
|---|---|---|---|
| A 向量切片 | `semanticRetrieve` | Top-K 切片 | 余弦 [-1,1] |
| B 图谱节点 | `graphRetrieve`（已实现） | Top-K 节点 | 余弦 [-1,1] |
| C TF-IDF | `rag.retrieve`（现有） | Top-K 切片 | 混合分 [0,~0.9] |

### 分数归一化（量纲统一）
三条路量纲不同，各自**批内 min-max** 归一化到 `[0,1]`：
```
norm(x) = (x - batchMin) / (batchMax - batchMin)
```
- `batchMax === batchMin` 时该路 `norm = 1`（无区分度，交由其他路主导）。
- 余弦负值由 min-max 自动压缩到 [0,1]。

### 联合融合公式
```
finalScore(i) = α·normA + β·normB + γ·normC + δ·bonus
```
- `bonus`：图谱节点命中 `+0.05`（鼓励图谱路径优先呈现）。
- **切片↔节点去重**：若切片 id 经 `findNodeBySourceId` 能映射到某节点，融合时只保留 `kind:'node'`（语义更丰富、带前置链）。

### 参数配置表（建议值）
| 参数 | 建议值 | 说明 |
|---|---|---|
| `topK`（每路） | 5 | 与现有 `retrieve` 一致 |
| `finalTopK`（合并后） | 5 | 最终上下文切片数 |
| `α`（向量路） | 0.45 | 语义召回是本次升级核心 |
| `β`（图谱路） | 0.30 | 图谱语义 + 前置链 |
| `γ`（TF-IDF 路） | 0.25 | 保留词法精确支撑 |
| `δ`（来源奖励） | 0.05 | 图谱命中加分 |
| `minScore`（图谱路） | 0.15 | 防噪声节点 |

> **权重约束**：`α + β + γ = 1.0`（0.45+0.30+0.25），`δ` 是外加奖励不计入归一权重。

### 边界情况
| 情况 | 处理 |
|---|---|
| `graph` 为 null | 退化为「向量+TF-IDF」双路，`β=0` |
| 向量路空（query 全停用词） | `α` 临时置 0，靠 TF-IDF + 图谱 |
| 三条路都空 | 返回空，走现有「无数据」提示 |
| 同分并列 | 图谱节点优先，再按 `_exact_matches` 兜底 |

## B.3 关键 API 契约（`vectorMemory.js`）

```
addMemory(type, text, meta)       // type: 'diagnosis' | 'plan' | 'admission' | 'qa'
queryMemory(query, { topK=3, minScore=0.18 })
  -> [{ id, type, text, score, ts, meta }]  按 score 降序
clearMemory()
```

- **存储**：`localStorage['vector_memory']`，结构 `[{ id, type, text, vector, ts, meta }]`
- **容量**：上限 200 条，超出按 `ts` 淘汰最旧
- **召回阈值**：`minScore = 0.18`（与 `graphRetrieve` 的 0.15 同量级，向量记忆语义应更严格）
- **向量**：复用 `textToVector`（`name + text` 聚合，L2 归一化）
